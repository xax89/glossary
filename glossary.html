檔案與電腦基礎

4
檔案路徑Path

描述「檔案放在哪裡」的地址，例如 下載/GitHub.dmg 表示在下載資料夾裡。

遇到：安裝完找不到東西、要告訴 AI「檔案在哪」。從「下載／文件」資料夾開始找，通常就找得到。

資料夾／目錄Folder / Directory

裝檔案的容器，可以一層包一層，就像實體文件夾。

遇到：下載的專案常是一個資料夾，裡面再放很多檔案；別只解壓其中某一個檔。

副檔名File Extension

檔名最後的 .py、.txt、.zip 一小段，標示檔案類型。

遇到：搞不清楚「哪個檔案能開」時先看副檔名；完整清單見「副檔名」分頁。

安裝／版本Install / Version

安裝＝把軟體裝進電腦；版本＝軟體的更新代號（例如 Python 3.12）。

遇到：照教學「下載 → 雙擊 → 下一步 → 完成」；報錯說「版本太舊」就升級。

終端機與命令列

4
終端機Terminal

用「打字」對電腦下指令的視窗，Mac 內建 App 就叫 Terminal。

遇到：教學寫「打開終端機輸入⋯」時。指令可以整段複製貼上，不用自己打。

指令Command

打進終端機的一段文字，例如 ls（列出檔案）、cd（切換資料夾）。

遇到：複製教學的指令時。貼上後按 Enter，有反應多半就成功了。

執行／運行Run

讓程式「跑起來」的動作。

遇到：輸入 python 檔名.py 後看到輸出，就代表執行成功。

環境變數Environment Variable

電腦的全域設定；最常遇到 PATH——決定你在哪個資料夾都能直接呼叫 python。

遇到：安裝後輸入指令卻顯示 command not found，多半是 PATH 沒設好，把報錯貼給 AI 即可。

Git 與 GitHub

6
GitGit

記錄檔案修改歷史的工具，像「檔案的時光機」，任何版本都能回溯。

遇到：教學叫你「安裝 Git」。裝好後日常就是 commit／push／pull 三兄弟。

Repository（repo）Repo

一個專案＝一個 repo，包含所有檔案＋完整修改歷史。

遇到：GitHub 上每個專案頁面就是一個 repo；下載別人的專案＝clone 一個 repo。

CommitCommit

把目前進度「拍一張快照」存下來，並寫一行說明。

遇到：改完程式後執行 git commit。好習慣：小步 commit，說明寫清楚。

PushPush

把本機的 commit「上傳」到 GitHub。

遇到：想讓 GitHub 上的檔案變成最新版時。記住口訣：先 commit，再 push。

PullPull

把 GitHub 上別人改過的內容「抓下來」到自己電腦。

遇到：多人協作、或換電腦繼續工作、想更新到最新版時。

CloneClone

把別人的 repo 完整複製到自己電腦（包含歷史記錄）。

遇到：想「下載」某個專案來用、來研究時。

程式與開發概念

5
程式碼Code

寫給電腦看的指令文字；你學的 Python 就是一種程式語言。

遇到：用 VS Code 打開 .py 檔，看到的內容就是程式碼。

編輯器Editor

專門寫程式的軟體，最常用的是 VS Code。

遇到：安裝 VS Code 後，用「開啟資料夾」打開專案資料夾來寫 code。

腳本Script

一段自動化小程式，例如「自動整理下載資料夾」。Python 特別適合寫腳本。

遇到：想讓重複的事自動做時，就是寫腳本的時機。

報錯／錯誤訊息Error

程式出錯時跳出的提示（通常是英文）。它是程式給你的線索，不是在罵你。

遇到：幾乎每天。SOP：整段複製 → 貼給 AI → 跟著改，最有效率。

APIAPI

兩個程式之間溝通的「點餐窗口」：你叫資料，它出資料。

遇到：想讓程式抓天氣、匯率、股市資料時；也是「連接器」背後的原理。

AI 與新工具

5
Prompt（提示詞）Prompt

你對 AI 說的話＝任務描述。說得越清楚，結果越好。

遇到：每次跟 AI 對話都是在寫 prompt；「目標＋材料＋格式＋驗收標準」四件套最有效。

Agent（智能體）Agent

能自己拆解任務、調用工具的 AI（豆包工作就是 Agent）。

遇到：任務模式／工作模式裡的我。不用懂原理，會下指令就行。

模型Model

AI 的「大腦」；不同模型擅長的事情不同。

遇到：生成結果不理想時，可以問問換個模型／模式是不是更好。

額度Quota

你能使用某功能的次數或時長限制。

遇到：提示「今日次數用完」時；免費版次日重置，訂閱則有更大額度。

上下文Context

AI 記得的先前對話內容。

遇到：新開對話後 AI 忘了前面的事＝上下文斷了；把重要資訊重新貼上即可。

前端與後端（端的地圖）

6
前端Frontend

使用者看得到的一切：網頁排版、按鈕、手機 App 畫面。你點得到的都算前端。

遇到：想讓網頁變漂亮、按鈕會動 → 學 HTML／CSS／JavaScript。

後端Backend

躲在伺服器跑的程式：登入驗證、存資料、算價格。使用者看不到，但功能全靠它。

遇到：資料要存起來、要算東西、要驗證帳號 → 那是後端的事。

全端Full-stack

前端＋後端都寫得動的人。

遇到：看到職缺寫「Full-stack」→ 就是要前後端都懂。

APIApplication Programming Interface

前後端之間傳資料的「服務窗口」：前端呼叫、後端回應。

遇到：App 要抓天氣、匯率、股市資料 → 通常是透過 API 向後端要。

客户端Client

使用者的裝置那端：手機、電腦、瀏覽器。

遇到：安裝 App＝在客户端裝程式；跟「伺服器」相對。

服務端Server

提供服務的電腦那端（機房／雲端）。

遇到：看到「伺服器錯誤」＝後端那台電腦出問題。

終端機入門指令

9
pwdprint working directory

顯示「你現在在哪個資料夾」。迷路時的第一條指令。

範例：輸入 pwd → 輸出 /Users/chenjieti

lslist

列出目前資料夾裡的所有檔案。

範例：ls -la 顯示更詳細資訊（含隱藏檔）——新手最常用的是這個。

cdchange directory

切換資料夾。三個固定用法必記：cd 資料夾名 進入、cd .. 回上一層、cd ~ 回主目錄。

範例：cd 下載 後再 pwd，會發現位置變了。

mkdirmake directory

建立新資料夾。

範例：mkdir 我的專案 → 建立名為「我的專案」的資料夾。

touchtouch

建立一個空檔案（檔案已存在時則只更新時間）。

範例：touch 筆記.txt → 建立空的筆記.txt。

cpcopy

複製檔案。複製整個資料夾要加 -r。

範例：cp 筆記.txt 備份.txt；cp -r 專案 專案備份。

mvmove

移動檔案，也能「重新命名」。

範例：mv 舊名.py 新名.py（改名）；mv 檔案.txt 下載/（搬家）。

catconcatenate

把檔案內容直接印在螢幕上，看小檔案最快。

範例：cat 筆記.txt → 立刻看到全部內容。

openopen（macOS）

用預設程式打開檔案或資料夾（Mac 專屬）。

範例：open 下載 → 直接跳出 Finder 視窗；open 報告.pdf → 用 PDF 程式打開。

Git 日常六條

6
git clone複製專案

把別人的 repo 下載到自己電腦。

範例：git clone https://github.com/某人/某專案.git

git status查看狀態

看「現在改了哪些檔案」。想確認自己做到哪，打這條就對了。

範例：改完檔後打 git status → 紅色＝還沒暫存，綠色＝已暫存。

git add加入暫存

把修改「放進暫存區」，準備要 commit。

範例：git add 檔名.py 加單一檔案；git add . 一次加全部。

git commit拍快照

把暫存區的修改存成一筆歷史紀錄，必須附說明。

範例：git commit -m "修正輸入錯誤"。說明用中文也可以。

git push上傳

把本機的 commit 上傳到 GitHub。

範例：git push。口訣：先 add → 再 commit → 最後 push。

git pull下載更新

把 GitHub 上最新版本抓回本機。

範例：換了電腦繼續做 → 先 git pull 再開工。

Python 起步

4
python3 --version確認版本

確認 Python 有沒有裝好、版本是多少。

範例：輸出 Python 3.12.x 就是正常；出現 command not found 代表沒裝好。

python3 檔名.py執行程式

執行 Python 檔案，程式會跑給你看。

範例：在放著 hello.py 的資料夾輸入 python3 hello.py。

python3互動模式

直接進入 Python 互動視窗，一行一行試語法，適合測小東西。

範例：輸入 python3 → 出現 >>> → 打 print("hi") → 按 Ctrl+D 或輸入 exit() 離開。

pip3 install安裝套件

安裝 Python 套件（macOS 常寫 pip3）。

範例：pip3 install requests；裝完通常會要求重新開啟終端機。

終端機進階

10
rmremove

刪除檔案。刪了就沒有垃圾桶，執行前再三確認。

範例：rm 暫存.txt；rm -r 資料夾 是連資料夾一起刪——新手先用 mv 移到別處，別急著 rm。

|pipe 管線

把前一個指令的輸出「丟給」下一個指令處理。

範例：ls | grep py → 只列出檔名含 py 的檔案。

>redirect 重新導向

把原本顯示在螢幕上的輸出，改存成檔案。

範例：python3 程式.py > 結果.txt → 結果存檔而不是噴滿螢幕。

&&and 接續執行

前一個指令「成功」才執行下一個。

範例：cd 專案 && python3 程式.py → 先進去資料夾再跑程式。

Ctrl+C中斷

中斷正在跑的程式。程式卡住、迴圈跑不完時的好朋友。

範例：執行太久沒反應 → 按 Ctrl+C 停掉。

Ctrl+L清畫面

清空螢幕，等於輸入 clear。畫面亂掉時按一下，神清氣爽。

範例：畫面太雜 → Ctrl+L 回到乾淨狀態。

chmodchange mode

修改檔案的執行權限。初期很少用，遇到「Permission denied」才需要。

範例：chmod +x 腳本.sh → 讓這個檔可以被執行。

sudosuperuser do

以「管理者」身分執行，會要求輸入密碼。權力很大，不要亂用，尤其不要配 rm 一起用。

範例：安裝系統級軟體時教學會要求 sudo；其餘情況先問 AI。

brewHomebrew

Mac 的「軟體安裝商店」，用指令裝軟體。

範例：brew install git → 用 brew 安裝 Git。

curl下載／抓取

從網址抓資料到終端機，也能下載檔案。

範例：curl -O 網址 → 下載檔案到目前資料夾。

Git 與 Python 進階

3
git log看歷史

看 commit 歷史紀錄。

範例：git log --oneline → 一行一條，清爽好讀。

git branch分支

看目前在哪個分支；開新分支＝另開一條平行修改線。

範例：git branch 查看；git branch 新功能 開新分支。

venv虛擬環境

每個專案獨立的「套件隔離區」，避免不同專案打架。

範例：python3 -m venv myenv 建立 → source myenv/bin/activate 啟用（Mac）→ 用完 deactivate 退出。

AI Agent 操作

7
任務四件套目標＋材料＋格式＋驗收

下指令時說清楚四件事，AI 品質立刻升級：目標（要什麼結果）、材料（讀哪些檔案／連結）、格式（表格／文件／程式碼）、驗收標準（多長、要包含什麼）。

範例：「我要一份 Python 學習週計劃（目標），讀這份計劃書（材料），輸出表格（格式），每週要有實作項目（驗收）。」

先解釋再執行安全確認

要 AI 操作電腦或下指令前，先要求它「解釋這條會做什麼、會動到我電腦的哪裡」再執行。

範例：「這條指令會改動我的檔案嗎？先解釋一遍再跑。」

斜線指令 /slash command

輸入 / 開頭可直接呼叫特定技能或功能（例如 /某技能名），不用打字描述。

範例：對話框打 / → 跳出可選的技能／指令清單。

指定格式輸出控制

直接要求輸出格式，AI 會照做：表格、JSON、程式碼、繁體中文、字數限制⋯⋯

範例：「用表格列出，3 欄，每項附一句範例」→ 比「整理一下」清楚一百倍。

修正指令回饋迭代

不滿意就直說哪裡不滿意：「太長」「太難」「換個比喻」「只要重點」。AI 會照你的回饋修改，不用重開對話。

範例：「這份太專業了我看不懂，用跟 12 歲小孩解釋的方式重寫。」

報錯處理 SOP貼原文

看到報錯：整段複製貼給 AI，並說「用大白話解釋原因，再給我直接能跑的修正」。別自己瞎猜。

範例：「這段報錯是什麼意思？為什麼會發生？怎麼改？」

能力詞Skill / Connector / 定時任務 / 夥伴

AI Agent 的擴充能力名詞，看到時知道「這是幫 AI 加能力的工具」即可：技能＝特定領域的專業流程、連接器＝接外部系統／資料、定時任務＝到點自動執行、工作夥伴＝預設的專業角色。

範例：想讓 AI 定時整理資料 → 用「定時任務」；想接公司資料 → 用「連接器」。

網頁開發（前端）

8
響應式設計Responsive Web Design

讓同一個網頁依照螢幕寬度自動調整版面，手機、平板、電腦都好好顯示。寬度超過螢幕就會壞版。

遇到：手機看網頁「跑掉」時，多半就是缺響應式設計。

Media Query媒體查詢

CSS 的 @media 語法，指定「螢幕多寬時」套用另一組樣式。

範例：@media (max-width:560px){...} → 手機寬度（小於 560px）才生效的規則。

Viewport視窗設定

網頁的 meta 標籤，告訴手機瀏覽器「用真實寬度渲染」。

範例：<meta name="viewport" content="width=device-width, initial-scale=1"> → 每頁都該有，沒有它手機版一定壞。

iOS 自動縮放iOS Auto Zoom

iPhone 點擊字體小於 16px 的輸入框時，會自動把整個頁面放大——版面瞬間「跑掉」。

遇到：手機一碰搜尋框畫面就跳掉 → 輸入框字體要設 ≥16px。

安全區域Safe Area

iPhone 的瀏海、底部橫條（Home 指示條）會擋住內容，用 env(safe-area-inset-bottom) 留白避開。

範例：padding-bottom:calc(60px + env(safe-area-inset-bottom)) → 底部內容不被擋住。

CSS 前綴Vendor Prefix

Safari 對部分新 CSS 屬性要加 -webkit- 才認得，其他瀏覽器用原名。

範例：-webkit-backdrop-filter 和 backdrop-filter 兩行都寫 → 各瀏覽器都支援。

Flex 換行flex-wrap

Flex 容器加 flex-wrap:wrap，子元素放不下時自動排到下一行——窄螢幕不擠爆的秘密。

範例：.bar{display:flex;flex-wrap:wrap} → 手機上按鈕自動換行排列。

Sticky 工具列position:sticky

讓工具列捲動時黏在頂部，隨時能切換操作。

遇到：工具列太高會吃掉半個螢幕 → 手機上要壓扁（詞彙表工具列從 364px 瘦身到 118px）。

程式.css網頁樣式，跟 .html 搭配

程式.yaml / .yml設定檔格式，專案設定常用
程式.shShell 腳本，終端機批次指令（Mac／Linux）
程式.ipynbJupyter Notebook，資料科學分析筆記

程式.gitignoreGit 忽略清單，告訴 Git 哪些檔案不要上傳
程式.log程式執行紀錄檔，出問題先看它
程式.bak / .tmp備份檔／暫存檔，確認沒用就可以刪

互動使用小技巧：
  • 搜尋框會即時過濾目前分頁的內容——打「git」瞬間找出所有相關條目。
  • 副檔名分頁可先用分類按鈕縮小範圍（例如只看「程式」類）。
  • 卡關時先想等級：看得懂？→ 新手；要下指令？→ 初階／進階；不知道什麼檔案？→ 副檔名。
